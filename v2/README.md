# DA 광고 실적 대시보드 v2 (정적 HTML + 브라우저 저장)

기존 DA 대시보드(저장소 루트 `dashboard.py`)를 [첫구매 실적 대시보드](https://github.com/ryunj/first-dashboard) · [광고 신규 실적 대시보드](https://github.com/JHB116/ad-first-dashboard)와 같은 구조로 옮기는 중인 새 버전이다. **기존 대시보드는 그대로 두고** 숫자 비교용으로 함께 쓴다.

| | 기존 (`dashboard.py`) | v2 (이 폴더) |
|---|---|---|
| 데이터 | 접속할 때마다 원본 3개(로데이터 · 24년 · 목표) 업로드 | 처음 한 번 올리면 **이 브라우저에 저장**, 이후 새 날짜 파일만 |
| 계산 | Streamlit 서버(버튼마다 다시 실행) | 내 PC 브라우저(즉시 반응) |
| 24년 데이터 | 매번 같이 올림 | **한 번만** 올리면 고정 (2024-12-31 까지) |

**저장소에는 실적 데이터가 없다.** 원천은 서버에 저장하지 않고, 정리된 데이터는 보는 사람의 브라우저(IndexedDB)에만 남는다.

## 데이터 넣기 (PC 에서 백업 만들기 → 화면에 끌어다 놓기)

원천은 기존 대시보드와 **같은 DA 로데이터**(xlsb · csv · xlsx, 첫 행 `기간_일자` · `구분_*` · `카테고리` · `대상여부` · `지표_*`)다.
원천은 **PC 에서만** 읽는다 — Streamlit 서버는 원천을 받지 않아 메모리가 거의 들지 않고, 큰 파일 때문에 앱이 멈추지 않는다(광고 신규 실적 대시보드에서 권장하던 방식).

1. 이 저장소를 PC 에 내려받는다(GitHub → Code → Download ZIP, 또는 `git clone`) → `v2` 폴더.
2. **처음 한 번**: 24년 파일을 `make_backup_24.bat` 아이콘 위에 끌어다 놓는다(2024-12-31 까지만 쓰고 고정).
3. **매일**: 그날 25·26년 파일을 `make_backup.bat` 위에 끌어다 놓는다.
4. **목표가 바뀔 때**: 목표 파일(보고서 엑셀 — `월TOTAL요약(누계)` · `통합_전체` 시트)을 `make_targets.bat` 위에 끌어다 놓는다.
5. 열린 `backup` 폴더의 최신 `.json.gz` 를 대시보드 화면에 끌어다 놓는다(또는 **백업 파일 열기**) → 이 브라우저에 날짜 단위로 합쳐진다(같은 날짜는 교체, 24년 고정 구간은 24년 파일로만 바뀜, 목표 · 메모는 유지).

- 대시보드 위쪽에 `24년 저장됨(~24.12.31)`이 보이면 24년은 다시 넣지 않아도 된다.
- 직접 실행: `python build_data.py --y24 24년.csv --row 2526.xlsb --targets 목표.xlsx`
- PC 에서 대시보드를 띄워 보려면 `run_dashboard.bat`(`http://localhost:8502`).

## 리뷰 메모 · Gemini (무료 등급)

요약 시트의 리뷰 메모는 Gemini 가 1차 초안을 쓴다. 키가 없거나 실패하면 규칙으로 만든 기본 초안이 보인다.

1. [Google AI Studio](https://aistudio.google.com/apikey) 에서 API 키 만들기(무료 등급 · 카드 등록 불필요).
2. Streamlit Cloud → 앱 → **Settings → Secrets** 에 `GEMINI_API_KEY = "발급받은 키"` (선택: `GEMINI_MODEL = "모델 이름"` — 없으면 최신 Flash-Lite, 그 모델이 없으면 이 키로 쓸 수 있는 Flash 계열을 자동 선택).
3. Gemini 에는 화면이 계산한 요약 숫자(기본 초안)만 보낸다 — 원본 로데이터는 보내지 않는다. 무료 등급은 Google 이 보낸 내용을 서비스 개선에 쓸 수 있으니 사내 기준을 확인할 것.
4. 같은 조건(기간 · 단위 · 비용출처 · 필터)의 메모는 한 번만 자동으로 쓰고 저장한다. 다시 쓰려면 **Gemini 로 다시 쓰기**, 고치려면 **편집**.

### 공통

- 다른 PC · 브라우저로 옮기려면 **백업 내려받기** → 다른 곳에서 **백업 파일 열기**. 저장 주소(Streamlit Cloud / localhost)가 다르면 저장소도 따로다.
- 처음부터 다시 넣으려면 브라우저의 사이트 데이터(이 주소의 저장소)를 지운다.

## 화면

| 메뉴 | 내용 |
|---|---|
| **요약** | 주요 카드(광고비 · 거래액 · ROAS — 값 · 전년 · 전전년 · 목표와 각 비율), 나머지 묶음은 '다른 지표' 버튼으로 펼침. 실적 요약표(2단 머리글: 실적 · 전년비 · 전전년비 · 목표 · 목표비 — 월: 올해 전체 월 + 합계, '지난 연도 보기'로 24·25년도, 주 · 일: 범위의 최근 N개 · 전체). **리뷰 메모** 하나(요약 시트 전체 — Gemini 초안 또는 기본 초안 → 편집 · 저장). 지표별 추이(연도 겹쳐보기). 맨 아래 기간별 상세 실적 |
| **펼쳐보기** | 단계(기본: 비용출처 › 채널 › 매체 › 상품 › 캠페인, 최대 6단계 · 순서 변경)를 ▸ 로 펼치는 표. 검색 · 정렬 · 단계별 상위 N · 실적 미미 항목 숨김 · 핵심/전체 지표 · CSV, 칸 아래 비교(전년 · 전기 · 전전년, 캠페인 · 하위캠페인 · 기획전번호는 증감 없음). 이름을 누르면 그 항목의 연도 겹쳐보기 추이 |


범위 = 기준 기간에서 끝나는 최근 N개 기간(주 · 일은 '전체'도 가능). 월별 요약은 연도 기준이라 범위를 쓰지 않는다. 전년비 · 전전년비는 비교 날짜가 데이터에 모두 있을 때만 계산하고(24년 앞쪽처럼 비교 원천이 없으면 '–'), 24년 파일에 없던 지표(첫구매 · 신규 · 윈백)는 24년 값을 0 이 아니라 '–'로 둔다.

공통 조작 줄: **월별 · 주별 · 일별** · 기준 기간 · 범위 · **누계 / 일평균** · 비교(**전년 동기간 / 전월·전주·전일 / 전전년**) · 비용출처 묶음(TOTAL 등) · 접힌 **필터**(채널 · 매체 · 상품 · 부서 · 카테고리 · 디바이스 · 비용출처 · 대상여부 + 캠페인 · 하위캠페인 · 기획전 검색, 고른 조건이 버튼 옆에 한 줄로). 보기 설정은 브라우저에 남는다.

**드래그 합계**: 표에서 숫자 칸을 드래그(또는 클릭 후 Shift+클릭)하면 아래에 합계 · 평균 · 최소 · 최대. 광고비 · 거래액 · 수처럼 더할 수 있는 같은 단위일 때만 합계, ROAS · CPA 등은 평균만. Ctrl+C 로 엑셀에 붙여넣기, Esc 해제.

기준 기간은 '직접 지정…'으로 실적 기간 · 비교 기간을 날짜로 정할 수 있다(비교 기간을 직접 고치지 않으면 실적 기간의 전년 동요일을 따라감). 비용출처는 묶음(TOTAL 등) 또는 **비용출처(상세)** — 원천의 비용출처를 하나씩 골라 본다.

다음 단계(아직 기존 대시보드에서 보기): 전년비 리포트 · 매체/BPU/캠페인별 · 소재(AF코드) · 커스텀 · AI 실적 질문.

## 지표 · 기준 (기존 대시보드와 같다)

- ROAS = 거래액 ÷ 광고비 · CPA = 광고비 ÷ 가입수/첫구매수(순결제) · 신규CPA = 광고비 ÷ 당년신규고객수(순결제) · CR = 결제고객수 ÷ UV · CR(클릭기준) = 총결제고객수 ÷ 클릭 · CTR = 클릭 ÷ 노출. 비율 · 단가는 기간 합계끼리 나눈다.
- 일평균 = 기간 합계 ÷ 집행일수(고른 조건에 데이터가 있는 날짜 수).
- 전년비 = 동요일(364일 전) · 전전년비 = 728일 전 · 진행 중인 기간은 데이터가 있는 날짜만(MTD). 전월비 = 전월(진행 중이면 같은 일자까지) · 전주비 = 7일 전 · 전일비 = 하루 전.
- 비용출처 묶음(TOTAL · TOTAL(서비스비용미반영) · 거래액확대 · 신규고객확대 · 인지도제고)은 `dashboard.py` `COST_BUCKETS` 와 같은 목록.
- 주차 = 월~일, 'M월 N주차'는 목요일 기준. **차이 하나**: 기존은 연말연초 주(예: 24.12.30~25.01.05)를 달력 연도로 나눠 '2024년 1주차'에 12/30·31 이 섞였는데, v2 는 한 주로 본다.
- `tests/test_cross.py` 가 같은 가짜 원본으로 기존 `dashboard.py` 함수와 v2 결과(월 · 주 · 일별 실적 · 일평균 · 전년비, 비용출처 · 매체 · 디바이스 필터)를 대조한다.

## 배포

Streamlit Cloud → New app → 이 저장소 · Branch `main` · **Main file path `v2/app.py`** (기존 앱과 별도 앱). 보는 사람 제한은 앱 Settings → Sharing.
로컬 실행: `cd v2 && python -m streamlit run app.py`.

## 파일

| 파일 | 역할 |
|---|---|
| `dashboard.html` | 화면 · 상태 · 차트 · 표 · 드래그 합계 · 브라우저 저장 |
| `calc.js` | 공식 산식(지표 · 기간 · 비교 · 비용출처 묶음 · 백업 합치기). 화면과 테스트가 함께 쓴다 |
| `build_data.py` | 원천 → 백업(.json.gz), 24년 고정, 이어 붙이기, `--targets 목표.xlsx` 로 목표 포함. 로컬 CLI 와 Streamlit 업로드가 같이 쓴다 |
| `targets.py` | 목표 파일(보고서 엑셀) 읽기 — 기존 `load_targets_from_report` 와 같은 규칙 |
| `app.py` · `streamlit_component/` | Streamlit 래퍼(화면 + Gemini 리뷰 메모 중계) |
| `gemini_memo.py` | 서버 쪽 Gemini 호출(키는 Secrets 에만) |
| `make_backup.bat` · `make_backup_24.bat` · `make_targets.bat` · `run_dashboard.bat` | PC 에서 백업 만들기 · 대시보드 띄우기 |
| `tests/` | 가짜 원본 생성 · 기존 대시보드 대조 · 산식 단위 테스트 |

## 확인

```bash
cd v2
python -m pytest -q tests          # 기존 dashboard.py 와 숫자 대조 · 24년 고정 · 이어 붙이기
node --test tests/test_calc.mjs    # 산식 단위 테스트
python -c "from streamlit.testing.v1 import AppTest; at=AppTest.from_file('app.py'); at.run(); print(at.exception or 'OK')"
```

화면 확인용 가짜 데이터: `python tests/make_sample.py data/sample && python build_data.py --y24 data/sample/sample_24.csv --row data/sample/sample_2526.csv` → `backup/` 의 파일을 `dashboard.html` 에 끌어다 놓는다.
